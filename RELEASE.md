
The v1.0.0 release line is frozen to the versions and deployment target above.
Maintenance must follow [`docs/MAINTENANCE.md`](docs/MAINTENANCE.md) and must
not change Forgejo source, the Go runtime patch, build behavior, or supported
deployment assumptions without a new maintenance or upgrade cycle.

The final source commit is recorded in the release `build-info.txt` and in
the corresponding GitHub Actions run. That file is the authoritative
provenance record for the source SHA, Go source/toolchain hashes, iPhoneOS
SDK, deployment metadata, runtime instruction inspection, and signature
result. The release artifact is built with `-buildvcs=false`; source identity
therefore comes from the external provenance file rather than from a mutable
VCS string embedded in the executable.

## Artifacts

The release bundle contains `forgejo-ios`, `build-info.txt`, and
`SHA256SUMS`. When a pristine copy is distributed for device-side signing,
it is listed separately and is not confused with the host CI-signed working
copy.

```text
forgejo-ios           19dd23e3a78d13e1beb18a1e475d7b1a2c75959a0718d958905a0a540400218a
forgejo-ios-pristine  e8a8d55f9cb3a942bad8cb0a00e3b88201244e8e73b469b1d45884ab6347389d
```

The values above are the SHA-256 entries generated by the successful A7 CI
artifact and reproduced across the two latest checkpoints with unchanged
Forgejo build inputs.
Verify a downloaded bundle with:

```sh
sha256sum -c SHA256SUMS
```

CI verified the host ad-hoc signature with `codesign --verify`. The tested
device installation is a separate copy signed by `/usr/bin/ldid` with
[`scripts/ios/device-entitlements-no-container.plist`](scripts/ios/device-entitlements-no-container.plist);
its observed P14 SHA-256 was:

```text
device working copy: 90d21e21e14438b5edbc0745a326ffe4a3b3c95e763b9e3d6bab48f6fadb734e
```

That difference is expected. Preserve both the host checksum and the
device-installed checksum in an operator's handoff. Do not publish private
keys, credentials, runtime directories, databases, repositories, logs, or
backup archives with this bundle.

## Installation summary

1. Verify `SHA256SUMS` before transfer.
2. Copy the executable, launcher, and entitlement plist into a new rootful
   device tree with mode-`700` directories.
3. Copy the executable to a device-side working path and run `ldid` with the
   no-container entitlement plist. Confirm the entitlement with `ldid -e`.
4. Create `custom/conf/app.ini` with explicit paths, loopback `HTTP_ADDR`,
   `DISABLE_SSH = true`, and `START_SSH_SERVER = false`. Keep configuration,
   database, logs, and launcher state owner-only.
5. Start through `scripts/ios/run-forgejo.sh`, verify the version, runtime,
   HTTP readiness, SQLite integrity, and raw listener address, then stop
   cleanly. The full command sequence is in [`PORTING_IOS.md`](PORTING_IOS.md).

## Backup and security

Use [`docs/BACKUP.md`](docs/BACKUP.md) to stop Forgejo, create and verify an
owner-only backup, restore into a new empty root, review absolute paths, and
start the restored instance. The P14 disposable backup payload checksum was
`b7d7f1f7fa5c97e04c9deab4f06c170de98f1d035d9f83c25c5cda30336cc7bc`.

[`docs/SECURITY.md`](docs/SECURITY.md) is part of the release contract. A
checksum provides integrity, not confidentiality: Forgejo configuration,
SQLite data, repositories, and backups can contain credential-derived or
user-controlled material. Encrypt backups separately, keep them outside a web
root, and do not reuse disposable validation credentials.

## Known limitations

- Qualification is limited to the listed rootful `iPad4,4` / A7 / iOS 12.5.7
  target. Other devices, iOS versions, jailbreak layouts, and non-A7 CPUs
  require new evidence.
- Manual launcher operation is the currently qualified startup mode. The
  managed rootful LaunchDaemon implementation is host-validated and remains
  device-gated until the P18 reboot/crash checks pass. Arbitrary launchd
  hooks/tweaks, rootless deployments, and other devices are not qualified.
- Loopback HTTP is the safe default. Tailscale or a reverse proxy must use an
  explicit address and separate access controls; wildcard/public exposure is
  not qualified.
- The A7 runtime fallback has bounded workload evidence, not thermal,
  battery, capacity, or indefinite-soak qualification. Optional Forgejo
  services and external renderers remain deployment-specific.
- Backups do not contain the executable, signature, Go runtime, entitlements,
  logs, or external storage, and the backup script is not an encryption tool.
- Maintenance is limited to documented rebuilds of the frozen release matrix
  unless a new Forgejo or Go runtime update cycle is opened and revalidated.
