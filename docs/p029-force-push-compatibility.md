## Application findings

- `services/pull/comment.go:CreatePushPullComment` computes the old/new commit IDs, then calls `models/issues/comment.go:CreateComment`. That model commits the SQL timeline record. v15 creates no history refs. Normal branch updates (`services/pull/pull.go`) and AGit (`services/agit/agit.go`) both invoke it, conditionally notify on success, and do not provide a durable retry/reconciliation queue for pin creation.
- The prerequisite writes old and new refs separately **after** SQL insertion. A first/second ref failure leaves a committed timeline row with zero/one pins. A retry inserts another comment with another ID. There is no event identity or compensation. It also dereferences `comment` without checking the error from `CreateComment`, risking a nil dereference on a failed SQL insert. These are code-review findings, not injected-failure test results.
- `Comment.LoadPushCommits` reads commit IDs from SQL JSON and resolves Git objects. Existing P029 rendering tolerates a missing object; it cannot restore an object already collected by Git. Legacy pins can keep objects alive and must not be deleted during upgrade merely because a newer namespace is preferred.
- `modules/git/git.go:syncGitConfig` sets `receive.hideRefs=refs/pull/`. This is receive protection, **not** upload-pack privacy. The mirror change cannot replace that setting verbatim on v15: v15's private pre-receive handler has no development `preReceivePull` case and no force-push namespace case. The default path allows arbitrary refs to code writers. New namespace pins would be unprotected without an adapted handler; removing old hiding would expose legacy pins to mutation/deletion.
- Hooks are generated by `modules/repository/hooks.go:CreateDelegateHooks`, invoked via the configured Forgejo executable, and refreshed by `services/repository/hooks.go:SyncRepositoryHooks`. A port needs upgraded hook behavior for existing repositories, not just ref-name helpers. Do not remove owner custom hook files. No hooks on real repositories were installed or invoked.
- Outgoing push mirrors (`services/mirror/mirror_push.go`) configure explicit heads/tags push refspecs, and execute the mirror path through `git.Push`. Incoming `git push --mirror` is a different path: receive advertisement must omit both pin layouts while allowing supported PR-head behavior. Changing upload visibility would also alter supported historical commit access. Earlier isolated Git tests do not qualify the application path.
- `services/issue/issue.go:DeleteIssue` commits database deletion before removing only `refs/pull/N/head`. Legacy and new pin refs are not cleaned. The prerequisite/mirror pair broadens prefix removal but still deletes individual refs after SQL deletion; failure can orphan refs after the issue and retry context disappear. Prefixes must include the slash so PR 1 cannot delete PR 10.
- `services/issue/comments.go:DeleteComment` performs SQL/review cleanup and notifications, without pin cleanup. The upstream pair adds no timeline-deletion reconciliation. Repository deletion removes the whole disposable repo, which does not solve per-issue/comment cleanup.

## Synthetic qualification and limits

`tests/integration/p029_force_push_compatibility_test.go:TestP029ForcePushCompatibilityBaseline` uses only Forgejo's disposable SQLite fixture database and copied synthetic `commitsonpr` Git repository. It exercises the actual comment-creation, history-loading, HTTP commit-view, comment-deletion, and issue-deletion services. It deliberately asserts the current unsupported behavior, so a passing test is evidence for exclusion, not qualification of the proposed feature.

| Safe cleanup | Unsupported: orphan pins observed; no cleanup implementation imported. |
| Partial failures/retry | Missing object fails before SQL insertion; valid retry works. Post-SQL ref failure and crash recovery: NOT RUN, architecture absent. |

## Required future architecture before porting

1. Durable event identity and recoverable SQL/Git coordination: reserve a timeline/event ID, atomically update the old/new ref pair using `git update-ref --stdin` transactions, and record/reconcile incomplete work. Define crash recovery across SQL commit, Git updates, notifications and retries. A Git transaction alone cannot commit SQL atomically.
2. Preserve legacy refs and objects; define an idempotent migration or dual-layout reader/cleanup strategy, including collision validation. Never overwrite a pin that points to a different object. Already collected objects must remain explicitly unavailable.
3. Adapt v15 receive hooks and config to protect **both** layouts, preserving existing PR-head semantics; test registration, invocation, hook refresh and cleanup on synthetic repositories. Keep receive hiding separate from upload visibility and repository authorization.
4. Durable deletion cleanup for comments and PRs, safe prefix boundaries, idempotent retry after SQL deletion, and atomic ref deletion where appropriate. Account for closed/reopened PRs and retained history policy.
5. Application integration tests for new PRs, branch and AGit pushes, incoming and outgoing mirrors, denied pin writes/deletes, hidden advertisements, legacy/new fetch authorization, GC survival, SQL/ref failures, restarts and repeated migrations. Then exact-source host/security/frontend/production/A7/stock/matrix/artifact qualification.

No stable release authorization is granted. Device validation: **DEFERRED — OWNER APPROVED**.
